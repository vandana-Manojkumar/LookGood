🧠 AI Task Prompt: Deep Codebase Understanding for UKG
🎯 Your Mission

You are an autonomous AI engineering agent working at UKG.

Your mission is to fully understand the UKG source code repository, extract all technical knowledge, and generate detailed documentation that will be used to:

Train future AI models

Guide code generation

Enable testing and automation

Support engineering decision-making

📦 Input

You will be given:

A complete Git repository

All folders, files, and submodules

Git history (commits, branches, tags)

Example output formats (YAML/Markdown)

🔍 What You Must Do (Your Responsibilities)

You must scrape, analyze, and document every part of the codebase.

Break it down as follows:

1. 📂 Folder-Level Understanding

For each folder (including nested folders):

Name of the folder

Purpose (based on folder name, contents, or README)

Relationship to other folders

Main modules or files inside

2. 📄 File-Level Documentation

For every .py or relevant source file:

File path

Purpose of the file (summarized)

Top-level classes and functions

Whether it is a utility, controller, service, model, etc.

3. 🔧 Function-Level Documentation

For every function/method in every file:

Function name

Parameters and their meanings

Return value and type

Dependencies (other functions/modules called)

Exceptions raised

Docstring (if available)

Your own summary of what the function does

Example format:

file: billing/invoice_processor.py
function: calculate_due_amount(invoice)
description: Calculates remaining balance on an invoice, applying discounts and taxes.
inputs:
  - invoice: object (Invoice class instance)
returns: float (final amount due)
calls:
  - fetch_discount_rate
  - apply_tax
raises:
  - ValueError
  - InvoiceNotFound

4. 📈 Git History & Version Evolution

Using commit logs, extract:

Major changes across versions (v1.0, v2.0, etc.)

Added/removed/modified functions or files

Commit messages

Feature evolution (e.g., new billing logic added)

Refactors, performance optimizations, or breaking changes

Example:

version: v2.3
date: 2023-09-10
changes:
  - Added multi-currency support to billing
  - Modified: calculate_due_amount()
  - Deprecated: fetch_us_tax_only()
reason: International expansion

5. 🔁 Module Interaction Mapping

Track how different modules interact:

What services call each other?

What utilities are reused?

How data flows from UI → Controller → Service → DB

Visual or structured outputs are encouraged:

module: payroll
calls:
  - salary_calculator.compute_salary()
  - bonuses.calculate_bonus()
depends_on:
  - config/tax_rates.py

6. 🧠 Output Requirements

Output your knowledge as:

Markdown summaries for human reading

YAML or JSON for AI ingestion

Organized in folders:

docs/
├── v1.0/
│   ├── overview.md
│   ├── payroll.yaml
│   └── billing.yaml
├── v2.0/
└── current/


Optional: use vector storage (e.g., FAISS or Weaviate) for chunked retrieval.

🛠 Recommended Tools

If you are a tool-using AI, use the following:

Task	Tools
File crawling	os, glob, pathlib
Code parsing	ast, Tree-sitter, LibCST
Git history	git log, git diff, GitPython
Summarization	LLMs like GPT-4, Claude, or fine-tuned codellama
Storage	Markdown, YAML, JSONL
Embedding	OpenAIEmbedding, HuggingFace, text-embedding-ada-002

✅ Your output helps future AI generate or fix code confidently
